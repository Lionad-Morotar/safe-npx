## Problem Statement

`npx -y pkg@latest` 会直接拉取最新版。如果该版本刚被供应链攻击（Supply Chain Attack），用户立刻中招。需要一个透明替代工具，在调用 npx 之前根据发布时间和可配置策略锁定到安全版本。

## What Makes This Cool

一条命令替换。`snpx -y create-react-app@latest` 和 `npx -y create-react-app@latest` 体验完全一致，但自动规避可能有风险的新版本。用户零学习成本。

## Constraints

1. PoC — 概念验证，不需要生产级打磨
2. 单文件实现，~350 行（含导出、测试支持、帮助文档）
3. 零外部依赖（Node 18+ 内置 fetch）
4. 本地缓存，TTL 与 safety window 绑定
5. 参数完全兼容 npx（透传）
6. 拦截含 `@latest` 和裸包名的调用；其他情况直接透传
7. snpx 自更新提示：`--self-update` 检查新版本，遵循同样策略（24h 安全窗口）；检测到新版时提示用户运行 `npm update -g @lionad/safe-npx`（不自 exec）。`--unsafe-self-update` 可绕过安全窗口。

## Premises

1. 查 npm registry 版本列表 + 发布时间，优先用 `latest`；若太新则按策略 fallback — AGREE
2. CLI 名 `snpx`，参数完全兼容 npx — AGREE
3. 解析后 exec `npx pkg@resolved_version ...rest_args` — AGREE
4. 找不到满足条件的版本 → 报错退出，不 fallback — AGREE
5. 本地缓存（`~/.cache/snpx/{pkg}.json`），TTL 与安全窗口一致 — AGREE

## Recommended Approach

**Approach A: 单文件 PoC**

```
snpx/
├── package.json        # bin: snpx -> snpx.js
├── snpx.js             # 全部逻辑
├── test/
│   └── snpx.test.ts    # vitest
├── README.md
└── docs/
    └── main-design-*.md
```

核心流程：
1. 解析 argv：分离 snpx 专属 flag 与 npx 透传参数。识别 `@latest` 和裸包名作为拦截目标。
2. 检查 `~/.cache/snpx/{pkg}.json`，未过期则用缓存版本
3. 缓存 miss → fetch `https://registry.npmjs.org/{pkg}`
4. **安全版本解析算法**：
   - 获取 `latest` dist-tag 的发布时间和版本号
   - 若 `latest` 发布时间 >= `--time`（默认 24h），直接用 `latest`
   - 否则按 `--fallback-strategy`（默认 `patch,minor,major`）依次尝试：
     - `patch`：按发布时间排序后，`latest` 的下一个（即上一个发布的版本）
     - `minor`：同一 major 下，minor 号小于 `latest` 的最新版本
     - `major`：major 号小于 `latest` 的最新版本
   - 每个候选者也需满足发布时间 >= 安全窗口
5. 找不到满足条件的版本 → 抛出错误，进程退出
6. 写缓存，TTL 与安全窗口一致
7. `child_process.spawn('npx', [pkg@resolved_version, ...rest], { stdio: 'inherit' })` — 用 spawn 而非 exec（实时流式无上限，支持 TTY 继承）
8. **注意**：snpx 不注册 SIGINT handler，让 Ctrl+C 信号自然传播给 npx 子进程

缓存格式：
```json
{"version":"1.2.3","resolvedAt":1712000000000}
```

## CLI Flags

- `--time <hours>`：安全窗口时长（默认 24）
- `--fallback-strategy <str>`：逗号分隔的 fallback 顺序（默认 `patch,minor,major`）
- `--show-version`：打印解析到的版本并退出，不执行 npx
- `--self-update`：检查 snpx 自身更新（遵循安全窗口）
- `--unsafe-self-update`：立即检查自身更新，无视安全窗口
- `-h, --help`：帮助信息

环境变量：
- `SNPX_TIME`
- `SNPX_FALLBACK_STRATEGY`

## Open Questions

- 是否支持 scoped packages（如 `@vue/cli`）？→ 已支持
- npx 收到的是 `pkg@1.2.3` 而不是 `pkg@latest`，npx 会重新下载吗？→ 不会，npx 按精确版本缓存
- 裸包名（如 `snpx cowsay`）为什么要拦截？→ 防止 npx 在本地无缓存时隐式下载 `latest`

## Success Criteria

1. `snpx -y cowsay@latest` 成功执行，使用符合安全策略的版本
2. 缓存有效期内重复执行不触发 registry 请求
3. 所有 npx 参数透传且正常工作
4. `--show-version` 正确输出版本号且不执行 npx
5. vitest 测试覆盖：版本解析、缓存 TTL、fallback 算法、flag 解析
